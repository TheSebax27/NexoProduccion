MAPEO NEXO ERP <-> VISIONS ERP
Agosto 2026
==============================================================

NEXO puede funcionar de forma INDEPENDIENTE o en conjunto con Visions.
Cuando va en conjunto, el NexoSyncAgent sincroniza los datos entre
ambas bases de datos usando este mapeo como referencia.

Flujo de sincronizacion de Facturas:
  Visions → NEXO:  TareaExportarVentas lee MOVDETALLES filtrado por CENTROCOSTO y TIPDOC,
                    envia via RegistrarEventoEntranteAsync. Cada fila procesada se pre-marca
                    en NEXO_VentasExportadas para idempotencia.
  NEXO → Visions:  TareaSincronizarFacturasNexoVisions lee Facturas con StockDescontado=1
                    y ExportadaVisions=0, escribe en MOVDETALLES linea por linea, pre-inserta
                    en NEXO_VentasExportadas para evitar reimportacion, luego llama
                    marcar-exportada-visions (ExportadaVisions=1).
  Condicion: Solo facturas donde TODAS las lineas tienen mapeo en Integracion.MapeoArticulos
             para este CentroCosto se exportan a Visions.
  Nueva columna requerida: Facturacion.Facturas.ExportadaVisions BIT DEFAULT 0
  Ver: sql/migration_nexo_sync_v1.sql

--------------------------------------------------------------
SINCRONIZACION DE CATALOGOS (bidireccional automatica)
--------------------------------------------------------------

Ejecutada en cada ronda del agente (TareaSincronizarCatalogos).
Va PRIMERO dentro del bloque de sync (antes de ventas, articulos y facturas)
para que Marca/GrupoMenor/Presentacion existan en ambas bases antes de cualquier
sync de articulos en cualquier direccion.
Logica: si el codigo existe en un lado pero no en el otro, se crea via MERGE.
        Si ya existe en ambos, se actualiza nombre/descripcion.

Entidad           Clave sync          Direccion
---------------   ------------------  ----------------------
Marca             Codigo              bidireccional
GrupoMayor        Codigo              bidireccional
GrupoMenor        Codigo              bidireccional (requiere GrupoMayor previo)
IVA               valor IVA (int)     bidireccional (IvaID/Id son autoincrements independientes)
Presentacion      Codigo              bidireccional

IVA especial: el IvaID de NEXO y el Id de Visions son identities independientes.
La clave de union es el valor numerico del impuesto (Iva int = IVA int).

--------------------------------------------------------------
ARTÍCULOS PENDIENTES DE MAPEO (flujo automático)
--------------------------------------------------------------

Cuando Visions registra una venta de un artículo cuyo CodigoArticuloVisions
no tiene match en Integracion.MapeoArticulos NI en Catalogo.Tarjetas.Referencia,
el sistema (desde agosto 2026) NO lanza error al agente. En su lugar:

  1. sp_ProcesarEventoEntrante lanza THROW 54000
  2. RegistrarEventoEntranteAsync captura el 54000
  3. Hace UPSERT en Integracion.ArticulosPendientesMapeo con nombre/costo/precio
     que el agente ya incluyó en la petición (datos de TARJETA al momento de la venta)
  4. Devuelve 200 OK → el agente deja de reintentar el evento
  5. El evento queda en EventosEntrantes con Procesado=0 esperando resolución

Tabla Integracion.ArticulosPendientesMapeo:
  PendienteID, CentroCostoID, CodigoArticuloVisions, NombreVisions,
  CostoVisions, PrecioVisions, CantidadDetectada, FechaDetectado,
  Resuelto BIT, FechaResuelto

Flujo auto-creación (agosto 2026):
  Hay DOS vías de auto-creación:

  VÍA 1 — Desde venta (error 54000):
    Cuando llega una venta de artículo desconocido (54000), NexoApi auto-crea
    el artículo en Catalogo.Tarjetas y reintenta sp_ProcesarEventoEntrante.
    También crea Integracion.MapeoArticulos y marca ArticulosPendientesMapeo.Resuelto=1.

  VÍA 2 — Desde sincronización proactiva (TareaDetectarArticulosFaltantes):
    El agente lee TODOS los artículos de dbo.TARJETA en Visions (500 por ciclo)
    y para cada uno sin entrada en NEXO_TarjetasCambios llama SyncArticuloDesdeVisionsAsync.
    La API ahora auto-crea cuando no existe mapeo (igual que VÍA 1).
    Esto resuelve los 3470 pendientes sin necesidad de una venta.

  Datos usados para auto-crear:
    Referencia    = CodigoArticuloVisions / ReferenciaVisions
    Nombre        = DETALLE de Visions (o el código si viene vacío)
    TipoArticuloID = "Producto Terminado"
    PPublico      = PPUBLICO de Visions ?? 0
    StockMinimo   = 0, PuntoReorden = 0, Fracciona = 0

  Datos que llegan después (vía SINCRONIZAR_ARTICULO / TR_TARJETA_NexoCambios):
    Marca, GrupoMayor/GrupoMenor, IVA, Presentacion — NO vienen en el evento
    VENTA ni en la venta proactiva, solo en cambios explícitos de TARJETA.

  Nombre de cliente en ventas (fix agosto 2026):
    TareaExportarVentas hace LEFT JOIN dbo.USUARIOS ON NIT = m.NIT para obtener
    NOMBRE1+NOMBRE2+APELLIDO1+APELLIDO2 del cliente real. Ya no depende de
    m.CLIENTE (que en MOVDETALLES suele venir vacío).

  Cuando el Admin resuelve un pendiente manualmente:
  - Elige artículo existente en NEXO  →  solo se crea el MapeoArticulos
  - O crea artículo nuevo             →  INSERT en Catalogo.Tarjetas + MapeoArticulos
  - Tras crear el mapeo, ResolverArticuloPendienteAsync procesa retroactivamente
    todos los EventosEntrantes con ese CodigoArticuloVisions + Procesado=0

--------------------------------------------------------------
SINCRONIZACION DE EXISTENCIAS en SINCRONIZAR_ARTICULO
--------------------------------------------------------------

Desde agosto 2026, el evento SINCRONIZAR_ARTICULO (NEXO → Visions) SÍ actualiza
TARJETA.EXISTENCIAS con el stock actual de NEXO (suma de Inventario.InventarioStock
para ese artículo y CentroCosto). Antes solo actualizaba nombre/costo/precio.
El campo MARCA también se sincroniza (campo MARCA de dbo.TARJETA).

La API devuelve en EventoPendienteItem (NEXO → Visions):
  MarcaCodigo, GrupoMenorCodigo, PresentacionCodigo,
  IvaSiNo ("SI"/"NO" en NEXO → "S"/"N" en Visions), IvaValor, IvaDescripcion,
  Iva2 (→ VF4), IvaDescripcion2 (→ UBICA4).
El agente aplica todos en el MERGE de dbo.TARJETA con COALESCE para no
sobreescribir si el campo viene null.

--------------------------------------------------------------
NOTAS GENERALES DE SINCRONIZACION
--------------------------------------------------------------
1. La clave de sincronizacion principal de articulos es: NEXO.Referencia = VISIONS.TARJETA.REFERENCIA
2. Visions tiene PK compuesta (CENTROCOSTO + REFERENCIA). NEXO usa CentroCostoID
   del contexto del usuario autenticado para resolver el CENTROCOSTO.
3. GrupoMenorCodigo en Tarjetas es referencia blanda (sin FK formal) porque
   GrupoMenor tiene PK compuesta (Codigo + GrupoMayor) -- igual que en Visions.
4. Precios P (PPublico/PBodega/PCredito) = precio de venta por canal. U (UPublico/UBodega/UCredito) = utilidad/margen vs costo. Ambos grupos se sincronizan directamente.
5. NEXO.Presentacion.Fracciones = VISIONS.TARJETA.FRACCIONES — Tarjetas ya no tiene columna Fracciones propia; se obtiene via JOIN a Presentacion.
6. IVA doble impuesto: NEXO.Iva2 ↔ VISIONS.TARJETA.VF4 (numeric→decimal),
   NEXO.IvaDescripcion2 ↔ VISIONS.TARJETA.UBICA4 (nvarchar).
   Sincronizacion bidireccional desde agosto 2026 via TareaDetectarArticulosFaltantes,
   TareaImportarCambiosTarjeta y TareaAplicarEntradasInventario.
   Nota tecnica: TARJETA.IVAVALOR es smallint en Visions — Dapper requiere
   CAST(ISNULL(IVAVALOR, 19) AS DECIMAL(18,4)) para evitar error de materializacion.
7. MOVDETALLES es la tabla de movimientos de Visions (ventas, devoluciones, etc.).
   NEXO NUNCA modifica tablas nativas de Visions directamente -- solo el agente escribe en
   MOVDETALLES (exportacion NEXO→Visions) y en TARJETA.EXISTENCIAS (descuento de stock).
   El resto de Visions es de solo lectura para NEXO. Excepcion: tablas NEXO_* son propias.
8. Resolucion de conflictos de precios: gana el cambio mas reciente segun FechaModificacion.
   Buffer de 5 segundos para absorber la latencia del trigger al aplicar NEXO→Visions.

CORRECCIONES APLICADAS (agosto 2026)
--------------------------------------------------------------

1. SP ACTUALIZARTARJETA (VISIONSDBL1) - BUG CRITICO CORREGIDO
   WHERE [CENTROCOSTO] = CENTROCOSTO AND [REFERENCIA] = REFERENCIA
   → fue corregido a:
   WHERE [CENTROCOSTO] = @CENTROCOSTO AND [REFERENCIA] = @REFERENCIA
   El bug causaba que CADA UPDATE de tarjeta sobreescribiera TODAS las filas
   de dbo.TARJETA. Esto explicaba por qué todos los artículos llegaban con
   MARCA/GRUPOMENOR/PRESENTACION NULL en Visions.
   Se resetearon los 5 eventos CONFIRMADOS de artículos 15082710* a PENDIENTE
   para que se re-envíen con el SP corregido.

2. Ventas Visions en Facturación (NEXO Web) - arquitectura correcta
   La API NUNCA se conecta a Visions directamente.
   Se agregaron columnas TipDoc, NroDoc, NitCliente, NombreCliente a
   Integracion.EventosEntrantes. El agente ya enviaba TipDoc/NroDoc al registrar
   una venta; ahora RegistrarEventoEntranteAsync los guarda en la fila.
   Índice filtrado: IX_EventosEntrantes_VentasVisions (WHERE TipDoc IS NOT NULL).
   Endpoint: GET /api/integracion/ventas-visions — agrupa EventosEntrantes
   por CentroCostoID+TipDoc+NroDoc+Fecha, con paginación y filtros.
   Visible en Facturas.razor como MudExpansionPanel "Ventas de Visions".

3. BUG CANTIDAD=0 en ventas por caja - CORREGIDO (agosto 2026)
   TareaExportarVentas leía solo MOVDETALLES.CANTIDAD (unidades sueltas).
   Cuando una venta se registra como "1 caja", Visions almacena:
     MOVDETALLES.CANTIDAD = 0 (sin unidades sueltas)
     MOVDETALLES.CANTIDADCAJA = 1 (la caja)
   El agente mandaba Cantidad=0 a NEXO para todos los eventos de caja.
   Esto explicaba EventosEntrantes con Cantidad=.0000 para REMISIONes.
   CORRECCIÓN: El SELECT ahora calcula:
     CAST(m.CANTIDAD + (m.CANTIDADCAJA * ISNULL(NULLIF(t.FRACCIONES,0),1)) AS DECIMAL(18,4)) AS CANTIDAD
   Si FRACCIONES=0, NULLIF convierte 0→1 para que CANTIDADCAJA no se pierda.

4. Diagnóstico "5,0018" en ConsultaStock - NO era un bug de stock
   Lo que parecía ser stock=5.0018 era la lectura visual de dos celdas
   contiguas en ConsultaStock.razor: Cantidad="5,00" y Presentación="18 und".
   InventarioStock siempre fue 5.0000 (confirmado en DB y Kardex).

   via sp_ProcesarEventoEntrante — NUNCA tocan Inventario.InventarioStock.
